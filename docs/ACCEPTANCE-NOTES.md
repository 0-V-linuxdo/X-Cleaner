# X Cleaner 验收说明（给 Helium 验收）

验收按 `spec/x-blocker-features.md` §27 的清单进行。下面列出与原脚本行为**有意不同**的地方，验收时请按这里的预期判断。

## 已修正的「现状」

| 规格位置 | 原脚本（现状） | X Cleaner |
|---|---|---|
| §5.5 | 规则统计和 API key 不跨标签同步 | 两者都通过 `GM_addValueChangeListener` 跨标签同步；一个标签页保存 API key 或产生命中，另一个标签页的面板随之更新 |
| §8 第 10 步 | 走 Worker 正则的回复不再进入 AI 复核 | Worker 正则未命中后，若分类器结论是「建议 AI 复核」，仍会送审 |
| §15.5 | AI 规则生成期间修改**任何**配置都会中止生成 | 只有路由切换、AI 设置（启用、同意、endpoint、model、超时）或 API key 变化才会中止，错误仍为 `页面或设置已变化，AI 规则生成已中止。`；生成期间加词语、改名单不再中止 |
| §17.4 第 4 步 | 只勾选正文词且 AI 不可用时，不采用划词规则 | 只要勾选的词能生成通过校验的划词规则，就优先采用（AI 出错或返回 insufficient 时同样适用） |

## 其他有意的差异

- **名称与标识**：脚本名为 `X Cleaner`；面板宿主为 `#x-cleaner-ui`（原 `#x-reply-blocker-ui`）；tooltip 为 `.xc-native-tooltip`；样式按插件分开注入，而不是单个 `#x-reply-blocker-styles`。存储键与原脚本完全相同（`xReplyBlockerConfigV1` 等），所以可以直接沿用原脚本的配置；两个脚本不要同时启用。
- **插件化**：抽屉多一个「插件」标签，可开关每个功能插件；脚本菜单多一项 `X Cleaner 插件管理`，快捷键 Alt+Shift+X 打开完整的插件管理。插件管理与 Void++ 的设置界面对齐：左侧标签栏（插件 / 备份）和版本信息；分类标签默认「收藏」，另有「最近」「全部」和按标签分类；「搜索 N 个插件...」加 全部 / 已启用 / 已停用 筛选；两列卡片（图标、名称、「新」徽标、收藏、置顶、配置、开关，两行描述，作者页脚），置顶的排在前面，必需插件放在分隔线之后并变淡、开关禁用；滑杆图标打开插件设置，没有插件设置的插件会跳到它在抽屉里的页面。关闭某个插件后，它的判定器、页面和按钮会一起消失。
  - 「新」徽标沿用 Void++ 的规则：插件第一次出现时记下时间，之后 2 天内显示「新」，看过不会清除；必需和隐藏插件不记录、不显示。首次安装时所有可见插件都会标「新」2 天。
  - 作者页脚：插件没有声明作者时显示「X Cleaner Contributors」。
  - 与 Void++ 的一处差异：插件名过长时按单词换行（如 Account / Blacklist），而不是像 Void++ 那样截断成省略号，因为中文界面下卡片更窄。
- **主题**：跟随 X 页面背景色自动切换浅色 / 暗蓝 / 纯黑三套配色（规格只区分深浅两种）。
- **记录来源**：一条回复先被分类器或规则隐藏、作者随即自动入册后，重扫时该记录的来源会显示为「自动账号」（自动账号判定器优先级 50 高于词语、正则、分类器）。
- **AI 隐藏 + 入册**：AI 置信度 ≥ 0.9 时作者以「AI 自动」入册，之后同样显示为「自动账号」；记录上的 AI 状态文字保留。
- **规则弹窗校验超时**：弹窗与 AI 规则校验的 Worker 探测超时为 150ms（含 Worker 启动后的执行），黑名单页「测试样本」仍为 30ms。

## 自动化覆盖

- `bun test`：42 个测试，覆盖插件内核、路由、名单、正则、分类器（含 §11.6 示例）、配置导入、过滤集成（作用域、推荐分界线、占位条、自动入册与回滚、Worker 超时）、面板（标签、复查操作、黑名单默认子页、词语表单）、AI 复核（隐藏、ai-auto 入册、AI 关闭时零请求）、规则草稿分析。
- Chromium 冒烟（`scripts/smoke-extra.mjs` + `test/fixtures/x-status.html`）：FAB 与徽标、两条垃圾回复被隐藏、盾牌位于 Grok 左侧且 tooltip 为「分析这条回复」、点击盾牌打开本地草稿并通过校验、Esc 关闭、复查页五个按钮、方向键切换主标签、黑名单默认「账号」、窄屏全宽抽屉，控制台无报错。

真实 X 页面上的 DOM（Grok 按钮、caret 菜单、原生拉黑确认框、Grok 抽屉）只能在 Helium 里验证，这部分请重点看 §27 的「盾牌与规则弹窗」和「面板」两节。
